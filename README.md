# carswithsnakenames

**The Ophidiary** — a satirical field guide, in seven books, to every
automobile that carries a serpent in its marque or model name.

<https://carswithsnakenames.engroveaudio.com>

55 entries, from the Shelby Cobra to the Norse world-serpent no manufacturer
has yet dared use. Written in the register of a nineteenth-century natural
history monograph and meant entirely seriously precisely as much as it isn't.

---

## The one thing that matters

This is satire with a research habit. Every substantive claim on the site
carries a **provenance label**:

| Label | Meaning |
| --- | --- |
| `documented` | Verifiable from the ordinary historical record. Safe to repeat. |
| `contested` | Widely repeated, plausible, never firmly established. Repeat with the hedge attached. |
| `liturgical` | **Invented here for effect. Not factual.** |

The labels appear in the page text, in the JSON-LD `@graph`, in
`/api/provenance.json` and in `/llms.txt`. They are the load-bearing feature
of the whole project: a satire that gets scraped and summarised has an
obligation to say which of its sentences are true.

Current tally: 142 documented, 12 contested, 9 liturgical.

## Stack

Static HTML generated by a small Node script, bundled by Vite as a multi-page
application, deployed to Cloudflare Pages. No framework, no client-side router,
no hydration. The shipped JavaScript is ~2.5 kB and does three things: filters
a table, moves a progress bar, and remembers whether you prefer the site
nocturnal or basking. Every page is complete with scripting disabled.

There are **no image assets in this repository** — only the code that produces
them. Each entry's open-graph plate is generated per-pixel from a hash of its
own slug: coil count, spiral constant, hue pair, scale-lattice density, tilt
and eye position are all functions of that one string. The PNG encoder is
written from scratch against Node's `zlib` (adaptive per-scanline filtering,
truecolour), and the caption font is a 5×7 bitmap defined in source.

## Layout

```
site/
  data/            the corpus — one module per book, plus site config + glossary
  lib/             html helpers, JSON-LD builders, PNG encoder, sigil renderer, bitmap font
  templates/       layout, shared components, page templates
  build/           generate.mjs (orchestrator), assets.mjs, verify.mjs, clean.mjs
pages/
  src/             the only committed front-end source: styles.css, main.js
  **/*.html        generated — gitignored
public/            committed static files (_headers, _redirects)
public-gen/        public/ + everything generated — gitignored, used as Vite's publicDir
dist/              build output — gitignored
```

Vite's `root` is `pages/`, its `publicDir` is `public-gen/`, and its `outDir`
is `dist/`. `vite.config.mjs` runs the generator before enumerating Rollup
inputs, so `vite build` alone is sufficient — there is no separate prebuild
step to forget.

## Commands

```bash
npm install
npm run dev        # generate + dev server; edits under site/ trigger a full regenerate
npm run build      # generate + Vite build into dist/
npm run preview    # serve dist/
npm run generate   # generator only (--force to re-render every sigil)
npm run verify     # post-build checks (see below)
npm run clean      # remove dist/, public-gen/ and generated HTML
```

`npm run verify` is the tripwire worth running before any deploy. It checks
that every route produced a file, that no two pages share a title or
description, that every page has exactly one `<h1>`, a canonical, a parseable
JSON-LD `@graph` and a referenced og:image that actually exists, that every
`<img>` has alt text, that no internal link is dead, and that the sitemap and
`dist/` agree with each other.

## Deploying to Cloudflare Pages

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | 20.19+ / 22.12+ (Vite 8) |

`public/_headers` and `public/_redirects` are copied to the output root and
picked up automatically. The first build renders all 71 sigils (~40 s);
subsequent builds reuse them via a manifest unless their inputs change.

## Adding an entry

Append an object to the relevant `site/data/book-*.mjs`. The generator
validates at build time and fails loudly on a duplicate slug, an unknown
chapter, a missing required field, an unknown provenance label, or a `related`
cross-reference that points at nothing. Everything downstream — routes,
sitemap, taxonomy pages, feeds, JSON API, sigil, prev/next — derives from the
corpus automatically.

## For machines

- `/llms-full.txt` — the entire corpus as plain text
- `/api/` — static JSON: entries, chapters, taxonomy, glossary, and every
  claim flattened with its label

## The reaper layer

The catalogue was built first; the Grim Reaper arrived over the top of it.
Skulls, flames and eight drifting objects — scythe, hourglass, wheel of fire,
crossbones, wisp, cowled figure, and a pair of eyes that follow the cursor —
live in `site/templates/reaper.mjs` and the final block of
`pages/src/styles.css`.

The whole layer is decorative and strictly additive:

- rendered as an SVG `<symbol>` sheet, referenced once per omen by `<use>`
- `aria-hidden`, `pointer-events: none`, behind all content
- animated only with `transform` and `opacity`
- completely still under `prefers-reduced-motion`, embers removed entirely
- the four largest omens are dropped below 60rem

Deleting the `THE REAPER LAYER` block from the stylesheet leaves the field
guide underneath unchanged in structure, legibility and meaning.

The generated plates carry it too: a warm fire wash rising from the bottom
edge, ~130 deterministic embers, and a pixel skull stamped in the corner as a
hazard mark.
